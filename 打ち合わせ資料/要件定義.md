# 要件定義書: 人事評価システムの説明書
版: v0.1
更新日: 2026-10-29

## 1. 目的

このアプリは、複数の福祉事業会社で半期ごとの人事評価を1つの流れで回すためのもの。
評価の基準を決めるところから、アンケートの回答、点数の集計、昇格と昇給の判定、説明できるレポートまでを、同じ流れで進める。
この説明書は、すでに動いているアプリの全画面に番号を振り、役割ごとに「どの画面で何ができるか」と「何ができあがるか」を、見本のデータで示す。制度を直したときの反映範囲、回答から評価と確定への流れ、失敗したときのやり直し先も説明する。未決の運用条件は9章のQ01〜Q08に分けて示す。

## 2. 今の困りごと

以下は導入前の背景として整理したもので、現行アプリの未対応事項を示す一覧ではない。

- 等級要件・行動指針・KPI の評価の基準が、Googleフォームと表計算と自動処理の台本に散らばっている。
- 「基準の設定 → アンケートの回答 → 集計 → 昇格と昇給の判定 → 説明できるレポート」を、一つの流れで回せない。
- 評価される側に、なぜその結果になったかを説明する資料を、毎回手で作っている。
- 同じ困りごとが、複数の福祉事業会社で起きている。

## 3. 範囲

### 3.1 最初の版でやること

以下は、現行アプリで使える機能。

- 会社と使う人を用意し、役割ごとにログインして使う
- 会社ごとの評価の制度（等級・等級要件・行動指針・KPI・昇給）を設定する
- 評価期間とアンケートを作り、一般の社員が実績を答える
- しくみが点数と判定を出し、マネージャーが根拠を確かめて確定する
- 確定した結果と評価レポートを見て印刷し、使いにくい点を改善要望で送る

### 3.2 やらないこと

- 給与の支払いと、給与の計算のソフトとのつなぎ。昇給の判定と金額の設定までをアプリで行う。
- Google アカウントでのログイン。資格情報と運用の担当が揃うまで止めている。入れるかは Q05 で聞く。
- 未回答の人への自動のお知らせ（メールなど）。今は各役割がホームで気づく。入れるかは Q06 で聞く。
- 評価結果の PDF・Excel での書き出し。今はブラウザの印刷で紙か PDF にし、表は CSV で書き出す。入れるかは Q07 で聞く。
- 複数の評価者による合議。今は直属のマネージャー1人が確定する。入れるかは Q08 で聞く。

## 5. 業務の流れ

### 5.1 今

導入前の手順を、現行アプリとの比較用に整理する。

1. 会社ごとに、等級要件・行動指針・KPI の基準を表計算に書いておく。
2. 一般の社員が、Googleフォームで半期の実績を答える。
3. 回答を表計算に集め、自動処理の台本で点数を出す。
4. 上司が表を見て昇格と昇給を判断し、本人へ説明する資料を手で作る。

### 5.2 これから

以下は、現行アプリで行える手順。

1. システム全体管理者が、会社と会社の管理者を登録する。使う人はみなログインし、自分の情報とパスワードを整える (S01、S02、S03、S04〜S10)。
2. 会社の管理者が、制度設定ガイドに沿って等級・等級要件・行動指針・KPI・昇給を設定し、社員を登録する (S11〜S26)。
3. 会社の管理者が評価期間とアンケートを作って公開し、一般の社員が自分のアンケートに答えて提出する (S27〜S36)。
4. マネージャーが S38 で「提出済みの回答から評価を作る」を押すと、しくみが項目ごとのランク・点数・昇格と昇給の判定を自動で出す。
5. マネージャーが、判定の根拠を確かめ、上司の判断と理由を添えて評価を確定する (S37〜S42)。
6. 一般の社員が、確定した結果と評価レポートを見て印刷する。使いにくい点は改善要望で会社の管理者へ送る (S43〜S47)。

## 7. 守ること

- 速さ: どの画面も数秒で開く (例)。評価レポートの印刷は、図と文字の準備が済んでから押せるようにし、15秒で揃わなければやり直しを示す。
- 安全: ログインした人だけが入れる。記録は会社ごとに分け、他社の記録は見えない。役割ごとに見える範囲を限り、メニューに出さないだけでなく、画面を直接開いても通さない。一般の社員には、配点・ランクの境目・昇格に必要な点数・他人の結果を見せない。
- バックアップ: データの置き場所の「時間をさかのぼる戻し」で、7日前まで戻せる (今の契約)。新しい版を出す前に、戻り先を記録する。
- 使いやすさ: メニューは仕事の順に並ぶ。各ホームの最上部に「次にやること」を出す。取り消しにくい操作は、画面の中央に確認の小窓を出してから行う。一般の社員はスマホの幅でも答えられる。
- 量: 複数の福祉事業会社で使う。見本のデータは3社、会社に属する人は30人。評価は半期に1人1件。
- 止まったとき: 決まるまで、受付中のアンケートは締め切りを延ばして受け止める。どの時期に何日止まると困るかは Q04 で聞く。
- 使う時間帯: 半期ごと（上期 4月〜9月、下期 10月〜3月）。期を締め切ってから14日ほどで、集計・面談・確定を終える。

## 8. 用語

| 用語 | 意味 |
| --- | --- |
| ヘッダー | 画面のいちばん上の帯。アプリ名と、使っている人を出す |
| メニュー (サイドバー) | PC の画面の左に縦に並ぶ、画面を切りかえるボタン |
| フッター | 画面のいちばん下の帯 |
| モーダル | 画面の上に重ねて出す小窓 |
| 権限 | 役割ごとの、できることとできないことの決まり |
| バックアップ | データの控え。消えたり壊れたりしたときに戻せるように取っておく |
| 等級 | 社員の段階。等級1〜等級7のように、会社ごとに名前と数を決める |
| 等級区分 | 配点の型をまとめる単位。Beginner・Regular・Chief・AM・Manager の5つ。一つの等級区分に、一つか二つの等級が入る |
| KPI | 仕事の成果を測る項目。例: 利用者の満足度、記録の提出率 |
| 評価期間 | 評価をまとめる半期。上期は4月〜9月、下期は10月〜3月 |
| ランク | 項目ごとの出来の段階。A〜E の5段階で、A がいちばん良い |
| 等級要件 | 等級ごとに求める「支援について」「運営について」の行い。満たした割合を等級要件達成率として点数にする |
| 行動指針 | 会社が大事にする行いの観点。観点ごとに5段階で振り返る |
| 昇格の条件 | 上の等級へ上がるのに必要な点数と、報告書の提出のような点数の外の要件 |
| 確定 | マネージャーが評価を最終の結果として決めること。確定した評価は、あとで制度を変えても動かない |
| 操作する会社 | システム全体管理者が、いま設定する会社としてメニューで選ぶ1社 |
| 評価レポート | 1人の最新の確定した評価を、図とグラフ入りでまとめたもの。A4 縦は複数ページ、A3 横は収まるときに1枚で印刷する。ブラウザの印刷で紙か PDF にする |
| 仮パスワード | 会社の管理者が発行する、最初のログイン用のパスワード。一人ずつ違う値で、ログインしたら変えてもらう |
| 改善要望 | 各画面の右下から、使いにくい点を会社の管理者へ送る知らせ |
| CSV | 表計算ソフトで開けるファイル。社員の一覧や評価結果の受け渡しに使う |
| Claude Code | アプリを作る人が使う、開発を手伝うしくみ。届いた改善要望を受け取る |
| クラウド | インターネットの向こうにある、借りて使う機械。事務所に機械を置かなくてよい |
| サーバー | 画面から受け取った内容を処理し、結果や保存したデータを返す側の機械 |
