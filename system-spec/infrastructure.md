`★ Insight ─────────────────────────────────────`
- 失敗したときの守り方は3種類に分かれました。1回の batch に入るなら全部か無しか（**原子性**）。入りきらないなら書いた分を消す（**補償**）。先の書き込みを戻せないなら続きをやり直す（**前進回復**、roll-forward）。どれを使うかは「先に済んだ書き込みを戻せるか」で決まります。

## To-Be / Delta

> 本章の**規範**。上位概念 (要件定義書 U3 ゴール / U4 目標 / U9 具体的やりたいこと) を本章の serves_goals で絞り込んだ射影であり、設計知識 card (非規範の参考資料) とは役割が異なる。As-Is (現行実装の姿) は spec-state.json の管轄外のため本節では断定せず、到達点と、その到達を判定する観測点だけを規範として置く。

### 到達すべき状態 (To-Be)

- **G2**: 通常・強制の再読み込みや URL の直接表示は、直前の書き込み結果を必ず含む。
- **G6**: 等級の呼び名は、その会社の等級名だけで表す。行動指針の向け先・評価セットの区分・昇格の要件・警告文・アンケートのタイトル・ボタンのどこにも英語の区分名を出さず、等級名を変えると次の表示からすべてに反映される。
- **G8**: 役割ごとに、どのページを開けて、そこで何ができ何ができないかを、ページ名を単位にした同じ形で確かめられる。表示は実際の権限の判定と食い違わない。
- **G10**: 同じメールアドレスの人が、1つのアカウントのまま複数の会社に所属でき、会社ごとの役割・等級・上司で使える。所属していない会社のデータは見えない。
- **G13**: 並び順を持つ全ての編集画面で、矢印のボタンに加えて、長押ししたままのドラッグとキーボードでも並べ替えられる。
- **G17**: 事業所KGIの達成率の仕組み（メニュー・画面・計算・保存・表・列・文書・テスト）を残さず消す。賞与（仮）は KGI を使わない式（個人Pt＝KPI評価点の合計、賞与額＝個人Pt×昇給の設定の1点あたりの円）で出し続ける。
- **G28**: 評価・結果を確認する画面で「提出済みの回答から評価を作る」を試せるよう、提出済みの回答を含む受付中の評価期間の仮のデータ（氏名は実在しない「サンプル」など）を、手元の見本と本番の見本の会社の両方に用意する。

### 本章がかなえる具体的やりたいこと (U9)

- **I1**: 書き込みを Server Functions の共通の包みにまとめ、成功したら同じ応答で今の画面を作り直す（next/cache の refresh）。他タブへの通知と、将来のキャッシュの無効化の置き場も、この包みと画面側の共通口に持たせ、全ての書き込み画面をそこへ寄せる。
- **I6**: 応答に鮮度の手がかり（生成時刻）を載せ、反映されない報告を切り分けられるようにする。
- **I7**: 等級の呼び名を作る共通の関数を作り、区分名・行動指針のセット名・昇格の段階名・警告文・アンケートのタイトルの表示をすべてそこから作る。既定の等級名を『等級1』『等級2』『等級3』『等級4-1』『等級4-2』『等級5-1』『等級5-2』にし、既存の会社の等級名と、英語を含む表示名を一律に書き換える移行を入れる。
- **I9**: ページごとの権限を1つの定義（ページ・操作・役割ごとの可否・説明）にまとめ、『システムを管理する』に権限一覧ページを足し、利用者一覧に開閉できるボタンとモーダルを置く。説明はポインター・フォーカス・タップのどれでも出す。『Claude Code連携の鍵』を『Claude Code連携（システム開発者専用）』に改める。
- **I11**: 会社への所属を表にし、会社ごとに役割・等級・上司を持たせる。メールアドレスの重複はシステム全体で拒否したままにし、他社に既にアカウントがある人へ別の会社の所属を足すのは、全体管理者だけの専用操作にする。ヘッダーの会社の切り替えを複数の会社に所属する人にも出し、選んでいる会社が無いときは、有効な所属のうち会社名の順で最初の会社を開く。
- **I14**: 並べ替えを共通の部品にし、長押しのドラッグ・矢印・キーボードで動かせるようにする。保存には、並び順の全体を送る形を足す。
- **I18**: KGI のメニュー・画面・サーバー処理・計算・テスト・台帳の行を消し、賞与（仮）を個人Pt＝KPI評価点の合計で出す。2回目の Deploy で、3つの表と評価の2列を消すマイグレーションを当てる。
- **I31**: scripts/sample-data.mjs の見本の会社に受付中の評価期間を1つ足し、提出済み・下書き・未回答を混ぜる（作り方は buildSeed の使い回しのまま、INSERT だけ・見本の会社に紐づく行だけ）。手元の seed（scripts/seed-data.mjs）の受付中の期も、評価を作る画面で試せる人数の提出済みを持たせる。本番への投入は既存の db:sample:remote の手順で行い、実行の前に利用者の確認を取る。製品仕様 §14 の「受付中の期は作らない」を改め、§14 が挙げた影響（未回答の一覧に見本の人が並ぶ）を記す。

### 本章に効く確定意思決定

- **D-004**: 1つのアカウント（メールアドレス）のまま複数の会社に所属し、会社ごとの役割・等級・上司で使えるようにするとき、所属と『選んでいる会社』をどこに持つか。
  - 採択: 自前の所属の表を作り、選んでいる会社を cookie（hr_company）で持つ (`opt-membership-cookie`)
  - 目的適合: 会社ごとの役割・等級・上長を所属の表に持てるので、G10 を満たす。
- **D-005**: 並び順を持つ編集画面で、長押ししたままのドラッグによる並べ替えを何で作るか。
  - 採択: Pointer Events で共通の hook を自作する (`opt-pointer-hook`)
  - 目的適合: 長押しの時間やスクロールとの区別を要件どおりに作れるので、G13 を満たせる。キーボードと矢印のボタンも同じ部品に入れる。
- **D-006**: 権限一覧（役割ごとに、どのページを開けて、そこで何ができるか）を、システム管理のページと利用者一覧のモーダルでどう見せるか。
  - 採択: 1つの表に役割のタブでの絞り込みを足し、スマホの幅ではページごとのカードに切り替える（①②③の組み合わせ。利用者の回答から足した案） (`opt-combined`)
  - 目的適合: 役割の違いを表で比べ、タブで1つの役割だけに絞り、スマホではカードで縦に読めるので、ページ名を単位にした同じ形で G8 を満たせる。
- **D-007**: 権限の定義（各ページでできる操作と、その説明）をどこに置くか。
  - 採択: route-ledger.json に操作と説明を足す (`opt-route-ledger-extend`)
  - 目的適合: ページの可否・操作・説明が1つの台帳に揃い、表示が判定と食い違わないという G8 を満たせる。
- **D-008**: 他の会社に既にアカウントがある人を、別の会社にも所属させる操作を、誰が行えるようにするか。
  - 採択: 全体管理者だけが専用の操作（addMembership）で所属を足す (`opt-super-admin-only`)
  - 目的適合: G10 の『1つのアカウントのまま複数の会社に所属できる』を、全体管理者の操作で満たす。会社の管理者だけでは足せない。
- **D-009**: 複数の会社に所属している人が、選んでいる会社が無いとき（cookie が無い・所属していない会社を指している）に、どの会社を開くか。
  - 採択: 有効な所属のうち会社名の順で最初の会社を開く（同名は会社 id の順） (`opt-company-name-order`)
  - 目的適合: G10 の『会社ごとの役割・等級・上司で使える』を満たし、切り替えの一覧と同じ順なので、どの会社が開くかを利用者が予想できる。
