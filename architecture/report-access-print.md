# 評価レポートの入口・印刷の差分設計

[差分仕様](../specs/report-access-print.md)の R1〜R8 を、既存の認可・評価・印刷へ接続する。詳細の再定義は[製品仕様 §29](../docs/product/spec.md)と DD-025 に集約する。

| 責務 | 差分と既存依存 |
|---|---|
| 入口 | 管理者の社員詳細から既存 `/reports/[id]` を開く。既存の会社選択と `canViewEvaluationOf` を通す |
| 回答と評価の対応 | `responseId` で対応を特定し、既存の会社・本人・直属・確定条件を満たすものだけリンク。レポート自体は社員IDで最新確定を読む |
| 紙面 | レポート専用の操作が用紙サイズと準備状態を管理する。全紙用グラフとフォントの準備 → 印刷、15秒超過 → 通知・再試行。A3 横は前半とコメント / 推移と実績の左右2面で標準1枚、A4 縦は前半と後半を区切って長文も複数枚へ送る。A3 の紙面超過は印刷前に検知して A4 へ案内。ベクター図を保ち、本文への URL 展開を抑止し、`@page margin:0` と本文の12mm余白を組み合わせ、`box-decoration-break:clone`（webkit併記）でページごとに反復する。ブラウザ固有のヘッダーは印刷設定の案内で補う |
| 詳細の印刷 | 既存の明細印刷は「評価の詳細を印刷」とし、確定レポートへのリンクと区別する。未確定時の印刷も維持し、保存・確定などの操作パネルは紙へ出さず、詳細用 named page と本文余白の反復を使って URL・日時の余白表示を抑える |
| グラフ・表 | 既存の確定評価と項目内訳から KPI キー別の獲得点 / 配点・判定を評価者向けに作る。全確定期を時系列で並べ、等級ラベルと正規化した達成率を折れ線・表で示す。本人向けは既存の射影で点数を除き、等級要件の達成率を使う。保存列や再計算は追加しない |
| 基準帯の黒線 | 評価詳細の `ThresholdBand` → `buildThresholdScale` は実績値を項目の単位・閾値・向きで位置へ変換する。得点の棒と区別する凡例、端へ寄せた範囲外の説明を付ける。現在の設定と保存した判定の出所を区別し、保存値を再計算しない。`markerClamped` の below/above で端の説明を分け、現在基準の帯は保存判定で着色せず集計時の判定を別記する |
| 集計 | `buildEvaluationsForCycle` は未指定と空配列を区別し、対象なしで書き込まない。会社別所属による対象判定は既存の Server Action に残す |

新しい保存先・API・PDF生成基盤は追加しない。個人データは公開文書や確認画像へ転記せず、検証には架空の見本を使う。仕様反映の経路と検証は[受領書](../docs/product/spec-receipts/2026-10-21-report-access-print.md)。
