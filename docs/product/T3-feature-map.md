# T3. 機能分解・実装計画 — 画面内改善要望

## 1. 最リスク仮説

> 機微な画面画像を扱っても、再送・失敗・会社境界を破らず、問題発生ページから管理レビューまで1本で完了できる。

検証方法: 実D1互換SQLiteへの失敗注入、API統合、4ロール/他社、4幅ブラウザ / 検証Slice: 1。
**成果物先行の1本目**: `/f/acme-token`から文章+任意画像を投稿し、会社管理者が一覧→詳細→状態/メモを更新する。
**他候補より先に作る理由**: 依頼の価値と最大のデータリスクを同じ縦切りで検証できる。

## 評価レポートの追加改善（2026-10-21）

| 業務 | 入口・処理 | 保存・境界 | 検証 |
|---|---|---|---|
| 管理者がレポートを見つける | 社員詳細 → `/reports/[id]` | 会社選択と既存の本人・直属・管理者判定 | 権限の肯定・否定、最新確定 |
| 回答から結果を確認する | 回答詳細 → 回答IDに対応する評価 | 本人は確定後、評価者は既存の担当範囲。別回答の評価を代用しない | 対応あり・なし・閲覧不可 |
| レポートを紙へ出す | 専用操作 → 全グラフ・フォント待機 → ブラウザ印刷 | 保存なし。用紙の初期選択は A4 縦。A3 横・左右2面で標準1枚、A4 縦・区切りと長文の追加ページ。A3 過長時は A4 案内 | 準備失敗・再試行、実PDFの向きと枚数、長文全文、URL不出力 |
| キー別点数と等級の推移 | 既存確定評価 → KPI 内訳・全期の折れ線と表 | 保存なし。評価時の等級ラベル、評価者向け点数、本人向け非数値の形 | 全期の並び・異なる満点の正規化・本人の点数除外 |
| 評価詳細の印刷 | 既存明細の印刷 → 詳細用 named page | 未確定時も維持。確定レポートへの入口と区別 | URL・日時の余白表示抑止、本文の欠落なし |
| 基準帯の説明 | 評価詳細 → ThresholdBand / buildThresholdScale | 保存値を変更せず、実績値・単位・範囲外・現在設定の参考図を区別 | 線位置、範囲外、保存判定と現在基準の不一致 |
| 対象なしの集計 | Server Action → `buildEvaluationsForCycle` | `undefined` は全員、空配列は誰も変更しない | 直属0人の実DB回帰 |
