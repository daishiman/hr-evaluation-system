# 人事評価管理システム — 軽量仕様メモ

最終更新: 2026-08-10 / サイズ判定: **L**（画面20枚超・4ロール・マルチテナント）

## 0. 誰の・何の課題か（一文）

**複数の福祉事業会社**の**評価される側と評価する側**が、Googleフォーム＋スプレッドシート＋GASに散在している等級要件・行動指針・KPI評価基準を、**1つのシステム上で「基準の設定 → アンケート回答 → 自動集計 → 昇格/昇給判定 → 説明できるレポート」まで一気通貫**で回せない、という課題。

## 1. 登場人物（4ロール）

| ロール | できること | 見えないもの |
|---|---|---|
| SUPER_ADMIN（システム全体管理者） | 全会社の情報を閲覧・会社の作成 | — |
| COMPANY_ADMIN（会社管理者） | 自社の全マスタ編集・評価セット設定・フォーム作成・評価確定 | 他社のデータ |
| MANAGER（マネージャー／上長） | 自社の評価対象者の情報・評価結果・評価基準を**閲覧のみ** | 他社のデータ・マスタ編集 |
| EMPLOYEE（評価される側） | 自分に割り当てられたフォームへの回答・自分の結果の閲覧 | **配点・ランク閾値・昇格必要点数・他人の結果**（APIレスポンスからも除外） |

## 2. データの数え方（最初に決めたこと・後から変えると移行が要る）

- **1件 = 1人 × 1評価サイクル（半期）** で評価結果1レコード（`evaluations`）。
- 評価サイクルは**半期**（例: 2026年度上期 = 2026-04-01〜2026-09-30）。
- フォーム回答は **1人 × 1フォーム（＝会社×等級×サイクル×版）で1レコード**（`form_responses`）。
- 金額は**円・整数**。率は**%・小数1桁まで**。日付は **ISO文字列(YYYY-MM-DD)**。
- **全業務テーブルに `company_id`** を持たせ、行レベルでテナント分離する。

## 4. 業務フロー（各1行）

1. **制度を作る**: 管理者が 等級 → 等級要件 → 行動指針 → 昇格要件 を登録する（初期値はシード投入済み）。
2. **評価セットを決める**: 33項目から「等級要件達成率（固定枠1）」＋7カテゴリから1項目ずつ、計8項目を選び、配点を合計100点で設定する。
3. **サイクルを開く**: 半期のサイクルを作り、評価セットを紐づける。
4. **フォームを作る**: 等級ごとにフォームを自動生成（等級要件・昇格要件・行動指針・KPI設問から組み立て）し、ビルダーで調整して公開する。
5. **回答してもらう**: 評価される側が公開URLで回答する（点数・閾値は一切表示しない）。
6. **集計する**: 分子・分母 → 実績値 → ランク基準テーブル参照でA〜E → 配点で得点化 → 8項目合計（100点満点）。
7. **判定する**: 昇格＝必要点数到達 かつ 昇格要件ゲート（受講後報告書提出）を満たす／昇給＝**8項目すべてA**。
8. **説明する**: 判定根拠（どの項目が何点で、なぜそのランクか）を保存し、レーダーチャートと一覧で提示する。

## 5. 入力作法（全画面で1組に統一）

- **空欄の意味**: 空欄＝未入力（0ではない）。数値0は明示的に「0」と入力する。
- **自動計算値**: 欄の中に初期値として入り、「自動」バッジを付ける。手入力すると「手入力」バッジに変わり、「自動に戻す」リンクが出る。
- **Enter**: 次の欄へ移動（フォーム送信はしない）。送信は明示的なボタンのみ。
- **分母のゼロ**: 分母欄は1以上を必須とし、0または空欄なら送信をブロックして日本語エラーを表示する。
- **単位**: 欄の右側に接尾辞で常時表示（件／%／日／点／円）。

## 6. 常時表示要素（適用範囲）

- **適用する**: フォーム回答画面（進捗・保存・戻る／次へを固定表示）、フォームビルダー、8項目選択画面、評価詳細。
- **適用しない**: ログイン、一覧系（スクロール量が少なく、退避先がヘッダーで足りるため）。
- 実装は共通レイアウト部品1箇所（`components/layout/StickyActionBar.tsx`）。

## 7. データのライフサイクル方針（3点）

1. **取込値と手修正を別枠で持つ**: フォーム回答（`form_answers`）は原本として不変。評価側の修正は `evaluation_items.override_*` に別枠で保存し、どちらの値を使ったか画面に出す。
2. **確定済みサイクルはマスタ変更で据え置き**: `evaluations.status = finalized` のサイクルは、その時点のランク基準・配点を `evaluation_items` にスナップショット保存する。後からマスタを変えても確定結果は動かず、差分は管理画面に通知する。
3. **突合は正規化キー**: 社員はメールアドレス（小文字化・trim）、KPI項目は `company_id + no`、設問は `company_id + question_key` を正規化キーとする。

## 8. 仮置き（未確定）の扱い

制度として未確定の論点は **`is_provisional` フラグ**を持たせ、画面上に「仮」バッジと注記を表示する。管理画面からいつでも変更でき、コードには一切ハードコードしない。詳細は `docs/product/backlog.md` の「未確定の制度論点」節。
