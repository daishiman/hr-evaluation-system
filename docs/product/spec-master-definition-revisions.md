### 7-8. 等級要件・昇格要件は、本文を上書きせず版として残す

等級要件と昇格要件は、過去のアンケートと評価が「そのとき何を聞いたか」を説明するための定義である。
そのため、本文など意味が変わる修正を、使用中の行への上書き保存にしてはならない。

#### 操作ごとの保存規則

| 画面の操作 | 保存するもの | 過去への影響 |
|---|---|---|
| 新しく追加する | 新しい id の起点版。`previous_version_id = null` | なし。次に作るアンケートから候補になる |
| 内容を直す | **必ず新しい id**。`previous_version_id` に直前の現行版 id を入れる | 旧行、作成済み・公開済みアンケート、評価は変更しない |
| 今後使わない | 現行版の `is_active=false`。内容と id は変えない | 次に作るアンケートから外す。いつでも戻せる |
| もう一度使う | 停止中の**現行版と同じ id**を `is_active=true` に戻す | 次に作るアンケートから再び候補になる |
| 過去版の内容を再採用する | 過去版を直接 active にせず、その本文を使った**新しい id**を現行版の後続として作る | 系譜を巻き戻さず、再採用した時点を説明できる |
| 並べ替える | 現行版の `seq` を更新する | 将来の構成だけを変える |
| 完全に消す | 同じ系譜の全版が未使用のときだけ、子から順に削除する | 1版でも使用実績があれば拒否する |

- **現行版**は、同じ系譜の中で後続版から `previous_version_id` として指されていない末尾の1行。`previous_version_id` には後続を1件だけ許し、枝分かれをDBの一意制約で止める。
- 改訂時は旧行を1列もUPDATEしない。旧版の `is_active` / `seq` も改訂時点の値として残し、後続版が存在するという事実だけで現行候補から外す。
- 意味の変更に含むものは、等級要件の `text`、昇格要件の `text` / `transition_label` / `is_gate`。等級、区分、種類は改訂APIで受け取らず、対象 id の保存済み値から決める。
- `seq` と `is_active` は意味そのものではなく、**これから作るアンケートでの選び方**なので、後続版がまだ無い現行版だけを更新できる。内容の改訂と同じリクエストへ混ぜない。
- 同じ内容への保存は新版を増やさない。2人が同じ現行版から同時に新版を作ろうとした場合は片方を `409` とし、再読込を求める。
- id を使う操作では、会社・等級・区分・種類を本文から信用しない。サーバーが id と操作会社で対象を読み、同じ会社・等級・区分の範囲で処理する。
- 等級要件の使用中上限は、会社・等級・区分ごとに10件。追加と「もう一度使う」は件数確認と保存を同じDB処理で行い、10件を超える変更を残さない。

#### アンケートと評価への反映

- 新版と `is_active` / `seq` の変更は、**次に作るアンケート**から使う。作成済み・公開済みアンケートは自動更新しない。
- 作成済みの下書きへ反映したいときだけ、回答が無いなど既存の安全条件を満たす「設問を同期する」を明示的に実行する。改訂保存と自動同期を一つの操作にしない。
- `form_questions` は採用した版の id と文言を保存し、評価はその写しから作る。`evaluation_requirements` / `evaluation_gates` も当時の版 id と文言を保つ。
- このため、等級要件・昇格要件の改訂、停止、再開は既存評価の stale 判定へ含めない。再集計してもフォームの写しが同じで結果が変わらないためである。

#### 画面の言葉と到達方法

- 使用中の現行版: `内容を直す` / `今後使わない`
- 停止中の現行版: `もう一度使う`。`戻す` や `適用` のように結果が曖昧な語は使わない。
- 過去版: `この内容をもとに新版を作る`。旧版そのものを使用中に戻すようには見せない。
- 「使わない項目 N件・もう一度使う」は一覧上部または区分見出しから開けるようにする。折り畳んでも入口を隠さない。
- 使用中が10件の区分では「もう一度使う」を押す前から無効にし、`先に使用中の項目を1件「今後使わない」にしてください` と次の一手を示す。
- 保存後は `次に作るアンケートから反映します。作成済みのアンケートと評価は変わりません` と反映時期を明記する。

#### 行動指針をどの等級に出すか

`/admin/behavior` では、上部の読み取り専用一覧と下部の単一等級編集フォームに同じ情報を二重表示しない。
各等級を1行または1カードにまとめ、同じ器の中に次を置く。

1. 等級名
2. `この等級に出す行動指針` の選択欄（`出さない` を含む）
3. その行だけの保存操作

見出しや確認文は `適用` ではなく、`Beginnerのアンケートにこの行動指針を出す` のように対象と結果を具体的に書く。
選択の変更は次に作るアンケートから反映し、作成済み・公開済みアンケートと評価は変えない。
等級・等級要件・昇格要件と同じく「対象の行で選び、その行で保存する」操作単位にそろえる。

#### 過剰な共通化をしない

今回共通化するのは、同じ性質を持つ**等級要件と昇格要件の版ライフサイクル**である。
すべての制度マスタをイベントストアへ移す変更は行わない。金額、閾値、下書きなどは保存理由と時間軸が異なるため、必要になった単位で既存の専用履歴または別仕様として扱う。
