# T2. 体験設計書 — 画面内改善要望

## 0. 先に作る代表成果物

最頻業務: 問題が起きた画面から一言と任意画像を送る / 代表縦切り: Widget投稿→D1→管理一覧→詳細→状態更新。
採用した構成: AppShell共通overlay + 管理2画面 / 決め手: 既存実装と全認証済み業務ページを1か所で覆える。
仮説: 自動撮影を既定にしつつ画像を外せると速度と機微情報保護を両立できる / preview確認点: 4幅、Light/Dark、Esc/Tab、失敗後再送。

## 1. ジャーニー(主要)

[改善要望を開く] → [一言と任意画像を整える] → [送る] → [管理者が状態とメモを保存]

**ピーク体験**: 元の画面を離れず、黒塗り注釈を付けて「ここ」を伝えられる瞬間。
**エンド体験**: 「送りました。内容は管理者の一覧に届いています。」

## 2. 画面目録と6状態

| 画面 | 理想 | 空 | ローディング | 部分 | エラー | オフライン |
|---|---|---|---|---|---|---|
| 共通Widget（認証済み業務ページ） | 自動撮影+本文、任意注釈 | 本文空欄はinline理由+focus | 撮影中/送信中を近傍表示 | 撮影失敗でも貼付/文章のみ | 400/413/429/500を回復文で表示し入力保持 | 通信失敗を表示し入力保持 |
| `/admin/improvements` | 未対応件数→状態/期間/route絞込→本文 | 投稿0件/絞込0件を分ける | server render中は既存loading | 画像は有無だけ表示 | 共通errorの復帰導線 | 再接続後に再読込 |

対象範囲はroute ledger 44件のうち、`AppShell`で表示する認証済み業務ページ。redirect専用`/`と未認証`/login`、global error/not-foundは投稿者を安全に確定できないため対象外。`/f/[token]`が認証後に内容を表示する状態はAppShell対象で、route patternは`/f/[token]`になる。

## 4. マイクロコピー

- トーン: 敬体、専門語なし、回復操作を明示。
- ボタン: 「改善要望」「撮り直す」「画像を外す（文章だけで送る）」「元に戻す」「送る」「対応状況を保存する」。
- エラー: 「改善したいことを入力してください。」「見送りにする理由を入力してください。」「入力内容は残っています。◯秒後に…」。
- 空状態: 「まだ要望は届いていません」「画像は添えられていません。文章だけで届いています。」

## 5. デザインシステム適用

Mode: A Graphite × Amber / primary: 既存primary / accent: 状態と主要操作だけ / テーマ: auto・light・dark / 永続化: 既存テーマのみ。改善下書きはReact state内のみ。
フォント: 既存IBM Plex Sans+端末和文 / ID・URL: 既存mono / ナビ骨格: 既存sidebar。Widgetはsafe-area内右下。
44px操作領域: coarse pointerの既存ルールを継承 / Light-Dark: 意味色token、注釈色は画像へ焼くため固定 / 黒塗り: `--mark-ink`固定。
