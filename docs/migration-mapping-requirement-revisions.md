# 移行後の等級要件・昇格要件を直すとき

親文書: [`docs/migration-mapping.md`](./migration-mapping.md) §11

| 操作 | 移行時id | 保存先 | 元データとの対応 |
|---|---|---|---|
| 今後使わない | 同じidの `is_active=false` | 現行版 | 移行元の定義は残る |
| もう一度使う | 同じidの `is_active=true` | 現行版 | 移行元との対応は変わらない |
| 内容を直す | 旧idは変更しない | 新id + `previous_version_id=旧id` | 新版は旧版から派生したことを追える |
| 過去内容を再採用 | 過去idは変更しない | 現行版の後続となる新id | 再採用した時点を新しい版として残す |
| 完全に消す | 系譜全体を判定 | 全版未使用の場合だけ削除 | 使用済みの移行元定義は消さない |

フォームは作成時に採用した版idと文言を `form_questions` へ写す。
評価もその写しを保存するため、移行元の版・後続版のどちらを使ったかを過去の記録から判別できる。

### 11-1. 見本用サンプルと放置評価通知の境界

PR #33 のマージ済みデータでは、サンプルの評価期間は5期すべて `closed` である。
2024年度上期〜2025年度下期の40評価はすべて `finalized`、2026年度上期は回答も評価も作らない空期である。
したがって #38 の `listStalledEvaluations()` が読む「closedかつ未確定評価」または「closedかつ提出済み・評価未作成」のどちらにも該当しない。
`scripts/sample-data.test.mjs` は生成したサンプルを実DBへ入れ、この問い合わせ結果が0件であることを固定する。
