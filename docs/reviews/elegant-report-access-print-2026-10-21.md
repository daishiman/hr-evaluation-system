# 評価レポートの閲覧・判断・印刷の改善レビュー

日付: 2026-10-21。開始点: main `4e5986c`（#96・#97取り込み済み）。

## フェーズ1：思考リセットと俯瞰

過去のPASS判定を根拠にせず、現在の仕様・コード・操作のつながりから再確認した。成果物は削除していない。俯瞰専任SubAgentの報告を受領してから、3系統の分析を並列実行した。

今回の対象は、システム管理者が各社のレポートを閲覧する、入口とURLを見つける、回答から評価へ進む、上長の理由付き判断を反映する、図入りのレポートを読みやすく印刷する、という一連の流れ。

最初の事実確認では、レポート・SVGグラフ・上長の判断変更は存在した。SUPER_ADMINも選択会社内の全社員を閲覧できる。未確認だったのは入口の分かりやすさ、読み込み途中の印刷、紙面の実物、A3対応。印刷の「ぼやけ」は報告された現象であり、原因をラスタ画像と断定しない。

## フェーズ3：統合した改善方針

優先順は、対象ゼロの集計範囲修正、既存レポートと評価への導線、明示的な上長判断の確認、印刷準備と用紙選択。独立する修正は並列化し、共通コードと仕様の統合・再検証は依存に従って行う。最大3サイクル。

追加の権限モデル、コメントの自動採点、別の帳票データ構造、全社のデータを無条件に返すAPIは不要と判断した。SUPER_ADMINは会社選択で各社を閲覧し、本人として読むときの非開示と未確定評価の非公開は維持する。

本番の入口は `https://hr-evaluation-system.daishimanju.workers.dev`。レポートのパスは `/reports/[社員の利用者ID]`。IDを推測したURLは案内せず、社員画面のリンクから開く。

今回の改善は既存feature `feature-evaluation-report-and-raise-judgment` の継続差分。主な追跡は Beads `hr-inn.6` / dev-graph `SYS-EVAL-REPORT-P06`。入口・印刷・確認の関連タスクとの対応は[仕様反映受領書](../product/spec-receipts/2026-10-21-report-access-print.md)で管理する。

実装との対応:

- 手法4・9・12・15・18: 社員詳細からの直リンク、最新確定期の明記、結論見出しを改善。
- 手法6・11・14・29: 回答IDで対応評価を特定する導線と、コメントとは別の明示的な上長判断を案内。
- 手法7: 集計対象の未指定と空配列を区別。直属部下がいない上長の処理で担当外を変更しない。
- 手法17・20〜22・26・27: `ReportPrintControls` がA4/A3と印刷準備を管理し、紙用SVGとフォントを待機。共通テンプレートを保持し、長文は追加ページへ送る。
- 手法8・16・28: 点数では見送りの評価を理由付きの上長判断で昇給ありにした後も、計算点・計算判定・社員の等級を変更せずレポートへ反映することを確認対象とした。

仕様差分は[受入R1〜R6](../../specs/report-access-print.md)、設計は[差分設計](../../architecture/report-access-print.md)、選択理由は DD-025 に集約し、同じ要件の再定義を増やさない。
