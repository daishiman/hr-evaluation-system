# ワークツリーの30思考法レビュー（2026-10-14）

## フェーズ1: 思考リセット・俯瞰

過去のレビューの結論を採用せず、現在の仕様・変更・実装・試験結果から再判定する。ファイルや作業中の成果物はリセットしない。

対象は `daishiman/改善要望対応` の未確定変更全体。中心は改善要望 S1〜S14 / A1〜A13（等級表示、ルート台帳と権限、会社所属、最新評価、提出状況、設定不足、並べ替え、選択肢、配置）。製品仕様とシステム仕様を正本とし、生成された計画は照合対象として扱う。テーマは AGENTS.md / DD-003 の契約を維持する。

初見の懸念（未検証の仮説）:

- 多数の画面・処理が同時に変更されており、表示上の共通化と認可・データ取得の共通化が一致しているか。
- 複数会社所属への移行後、旧 user の会社・役割を読む処理が混在していないか。
- 同じ回答・設問・評価・不足情報を別経路で組み立て、表示や保存の条件が食い違っていないか。
- 文書を増やしたことで正本・計画・記録に同じ契約が重複し、今後の更新箇所が増えていないか。
- 静的契約テストだけでなく、実際の画面→サーバー→ローカルDBの操作を試験できているか。

この俯瞰をもってリセットのゲートを完了。次に9・9・12種の思考法を3担当へ分け、読取り専用の並列分析を行う。全結果が揃うまでは実装改善に進まない。

### 仕様判断の確認点

次の2点は実装の変更で隠さず、利用者へ判断を依頼した。承認の逐語履歴は書き換えない。

- 無効/未選択cookieの復帰先: 製品仕様・現実装は最古の有効所属、過去の承認記録は会社名順。
- 他社に既存のメールの人への所属追加: 製品仕様・DD-004・過去承認は自動追加、現実装・後発の境界説明は全体管理者だけの専用操作。

その後、利用者が「ベストプラクティスの方を選択して実行を進めてください。」と選定を委任したため、エージェントが [DD-009](../product/design-decisions.md#dd-009-会社選択と既存アカウントへの所属追加の方針を統一した2026-10-14) を採用した。有効な保存選択を優先し、未選択・無効なら最古の有効所属へ復帰する。既存アカウントへの別会社所属追加は全体管理者だけの専用操作とする。具体設計はアプリの運用に合わせた判断であり、OWASPがこの2方式を一律に要求しているという意味ではない。

製品仕様・システム仕様・派生文書へ現行契約を反映し、原承認の質問・回答には訂正優先の記録を添えた。SPEC-001 / SPEC-002は解決済みとして [履歴](../product/backlog-session-notes.md) へ移した。会社名順と所属順を逆にした場合、会社を改名した場合、所属日時が同じ場合も、選択が安定し所属を毎回検証することを実DBで追加確認した。

既存94件のQAの原質問・原回答・従来の訂正・その他メタデータが不変であることを比較確認した。利用者の委任原文は `qa-v32-delegated-membership-policy`、具体的な裁定は `qa-v27` / `qa-v28` の `corrections` とDD-009に分けて記録した。6セルの主QAは維持し、新委任の参照を追加した。既存の生成器が原答を保持したまま、答の直後へ「訂正優先」の記録を出すことも確認済み。派生文書に残っていた現行契約の方針差は解消し、過去の評価digestは過去時点の証跡として保った。
