# ワークツリーの30思考法レビュー（2026-10-21）

## 対象と進め方

基準は `dbe6333`。評価レポート、昇給・昇格の判断、アンケート運用、評価セットの選択、事業所の達成率の仕組みの撤去、見本データと関連文書を含む作業ツリーを読み直した。既存の対策が正しいという前提を置かず、仕様と実装の対応から確認した。思考リセットのためにファイルを消していない。

1. 俯瞰を先に完了。取得・業務判断・描画・保存・配布という責務を確認した。
2. 読み取り専用の3 SubAgentで、下表の9・9・12種を並列分析。3件すべての報告を受け取るまで実装しなかった。
3. 分析を統合し、フォーム・帳票・確定と問い合わせに所有範囲を分けて並列実装。文書と全体検証は親が担当。改善と再検証は最大3回とする。

正本は [製品仕様](../product/spec.md)・[DD-020〜024](../product/design-decisions.md)・[システム仕様](../../system-spec/index.md)。本人向けと評価者向けのデータ境界、テーマ契約、既存の判断待ちは維持する。

## 文書の重複と配布順序の確認

- 生成された P02・P05 の schema 方針と P13 の手動公開手順には旧記述があるが、[計画レビュー §2](../product/spec-receipts/2026-10-20-evaluation-report-plan-review.md#2-task-ごとの読み替え) が該当箇所をすでに明示的に読み替えている。新たな仕様矛盾として数えず、README の文書入口からこの既存の対応表を案内する。
- `dev-graph` writer の dry-run は `package_member_requires_register_package`、`write_count=0` を返した。生成タスクや graph の直接書換えは行っていない。読み替えを別文書へ再転記しない。
- 配布は [デプロイ時の注意 §14](../deploy-notes.md#14-評価レポートと上司の判断の配布移行-00380039) を正本とする。0038 と0039はローカル検証で同居できるが、同じ Deploy に入れない。本レビューでは本番へ反映しない。
- `architecture/` の取り込み時点の写しと、DD の訂正も履歴として扱う。新しい判断で旧記録を消さない。

DTO の派生値削除と、取得側・純粋変換側の確定評価抽出の共通化は見送った。前者は型・契約への波及があり、後者は各層で必要な入力保証で、小さな反復を減らすために依存を増やす効果が見合わない。本人／評価者の型、対話用／印刷用チャートは要件が異なるため維持した。

変更前は型検査と文書検査が通過。全体テストは3,659件成功・1件skip・1件失敗。失敗は引き継ぎ手順書の URL を同じ URL のリンクで囲んだ書式で、規則に合わせて生の URL にし、該当79件の通過を確認した。

最初のテスト起動は Node x64 と arm64 用依存の不一致で失敗した。`pnpm install --frozen-lockfile` で実行環境に合わせて入れ直し、ロックファイルは変更していない。

可視UIの判定は **REPORT_ONLY / external-brand**。色の判定 dry-run は `eligibility.status=report-only`。既定 catalog の verify は profile 未導入で FAIL となるため、既定配色への移行の根拠にしない。AGENTS と DD-003 を優先し、テーマ契約と既存のレポート受入検証を用いる。

## 4条件と残る境界

対象は今回のワークツリーの変更と共通化で、本番配布の完了判定とは分ける。実装後の独立した3 SubAgentの読み取り再レビューでは、各担当の4条件すべてPASSで、新しい重大な指摘はなかった。実行検証も合わせた最終判定は次のとおり。

| 条件 | 判定 | 根拠 |
|---|---|---|
| 矛盾なし | PASS | 拒否文と実行できる操作、コメントの検査値と保存値、図と凡例を一致させた。旧計画は既存の読み替えに従う |
| 漏れなし | PASS | 省略・null・空文字、回答有無、状態×評価期間終了、片側だけ比較可能、会社×対象IDの回帰検証と主要フローのE2Eが通過 |
| 整合性あり | PASS | 編集規則・採点基準の問い合わせ・図表の枠・チャート寸法を共有し、本人向けの型と投影を維持 |
| 依存関係整合 | PASS | 純粋な業務判定を入口が参照。寸法定数は重い描画本体に依存せず、詳細取得は会社とIDで絞る。配布の2段階は既存正本を維持 |

既存の判断待ちは [現在の残課題](../product/backlog.md) を正本とする。SECURITY-013〜015、POLICY-011、OPS-017、生成章の取り込み digest の更新手段などを、今回の整理で解決した扱いにしない。
