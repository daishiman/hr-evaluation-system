# 目的

行動指針と KPI・評価セットの設定の作業を、少ない読み量で迷わず進められるようにし、設定とアンケートのどちらを後から変えても食い違わない状態を保つ。いまは行動指針の既定の分け方（等級1・2で1つ、等級3・4-1・4-2で1つ、等級5-1・5-2は出さない）から既存の会社がずれたままで、初期設定の説明は固定の文のため実際の割り当てと合わない。2つの画面は説明を最初から全て並べ、KPI・評価セットは1つの画面に全ての作業が載っている。アンケートの設問を直しても設定は変わらず、設定を直しても下書きのアンケートは古いまま残る。評価を作る画面を試せる提出済みの回答が見本に無く、共通部品は色と手応えの強弱が弱い。これらを1つの機能として整える（system-spec の G25〜G29・I26〜I33）。

## 到達状態

行動指針は既定の分け方を、新しい会社と既定からずれた既存の会社の両方で、等級の内部の識別子で持ち、初期設定の説明はいまの割り当てから作られる。行動指針と KPI・評価セットの画面は、最初に状態・件数・次にやることだけを見せ、詳しい説明と編集は開いたときに出す。KPI・評価セットは入口の等級区分ごとのカードから、等級区分ごとの設定・全等級区分に共通の設定・KPI 項目・KPI カテゴリの別の画面へ進め、KPI 項目は聞くことを1行ずつ並べる。下書きのアンケートで設定とつながった設問を直すと、保存と同時に元の設定へ反映する。設定を保存すると、回答0件の下書きを作り直し、回答のある公開中のアンケートには次の版の下書きを作り、確定前の評価を集計し直す。確定した評価とレポートは確定した時点のまま残り、写しを持つ全ての場所の追従の規則が文書と契約テストで押さえられている。手元の見本と本番の見本の会社に、提出済み・下書き・未回答が混ざった受付中の評価期間があり、評価を作る画面を試せる。全ての共通部品が、いまのテーマの変数から作るグラデーションと、押した・選んだ・開いたの手応えと、主の操作の強弱をそろえて持ち、テーマの契約テストは書き換えなしで通る。

## スコープ

- スコープ内: 行動指針の既定の割り当て（beginner・regular で1つ、chief・am1・am2 で1つ、manager1・manager2 は出さない）へ書き換えるデータの移行を足し、観点の文と会社が足した観点は残し、初期設定の説明をいまの割り当てから作る。DD-010 を改める DD を書く（G25・I26）
- スコープ内: 行動指針の画面の冒頭を1文とまとまりの状態（数・飛び飛びの有無）だけにし、理由・初期設定・点数の注記は開いたときだけ出し、編集部品にある同じ説明の繰り返しを1か所にまとめる（G26・I27）
- スコープ内: KPI・評価セットの入口を等級区分ごとのカード（等級の並び・項目数・配点の合計・状態・次にやること）とほかの作業への入口だけにし、等級区分ごとの設定・全等級区分に共通の設定（昇給の条件）・KPI 項目の追加と修正・KPI カテゴリをそれぞれ別の画面にする（G26・I27）
- スコープ内: KPI 項目は名前と分類を見出しにし、聞くこと A・B…を1行ずつ並べ、計算式と実績区分・単位・向きは開いたときに出し、表の形を使わず境界のあるカードとブロックで並べる（G26・I27）
- スコープ内: 下書きのアンケートで設定とつながった設問を足す・外す・文を直すと、保存と同時に元の設定へ反映し、評価セットの決まりや KPI の計算に合わなくなる保存は、合わない決まりと直す画面を示して断る。設定の保存と同じ権限・会社の絞り込み・409・制度の変更の記録を通す（G27・I28）
- スコープ内: 設定の保存で、回答0件の下書きのアンケートを作り直し、回答のある公開中のアンケートには次の版の下書きを作り、確定前の評価を集計し直し、変わったアンケートと評価を保存の結果の文で示す。DD-015・DD-016 を改める DD を書き、公開の前の検査は残す（G27・I29）
- スコープ内: 設定の写しを持つ全ての場所を一覧にして、参照・追従・確定した時点の写しのどれかに決め、契約テストで抜けを落とす。保存の後に関係する画面と他のタブを取り直し、いまずれている下書きを更新時刻の新しい方へそろえる（G27・I30）
- スコープ内: scripts/sample-data.mjs の見本の会社と手元の seed に、提出済み・下書き・未回答が混ざった受付中の評価期間を足し、製品仕様 §14 の「受付中の期は作らない」を改める（G28・I31）
- スコープ内: globals.css に既存の意味のトークンと color-mix だけで部品クラスを足し、ボタン・カード・見出し・選ぶ部品・状態の印・進み具合・数の面・知らせ・表・いまいる場所の印の全ての共通部品から使う（G29・I32）
- スコープ内: 押す・選ぶ・開く部品の状態（指を乗せた・押した・選んだ・開いた・focus-visible）の見分け、44px 四方以上の押せる面、1つの面で主の操作は1つ、段階的な開示と境界のはっきりしたカードを共通部品でそろえる（G29・G26・I33）
- スコープ外: 平賀配色への移行と新しい色のトークンの追加、テーマの契約テスト・T2-experience-spec.md §5・globals.css 冒頭の brand_color_* の書き換え（AGENTS.md と DD-003）
- スコープ外: 確定した評価と評価レポートを新しい設定で集計し直すこと
- スコープ外: 公開中・締め切ったアンケートの設問をその場で差し替えること
- スコープ外: 評価セットの決まりや KPI の計算に合わなくなる変更を、アンケートから設定へ反映すること（理由と直す画面を示して断る）
- スコープ外: 別の利用者が開いている画面への即時配信（WebSocket 等の push）
- スコープ外: 本物の会社のデータに仮のデータを入れることと、見本と文書に実在の氏名・評価値を入れること（公開リポジトリ）
- スコープ外: 利用者の確認を取らずに本番へ見本のデータを入れること（投入は既存の db:sample:remote の手順で、実行の前に確認を取る）
- スコープ外: 画面の組み替えを、I27 の2画面と評価を作る画面の外へ広げること（ほかの画面には共通部品の見た目と手応えだけが効く）
